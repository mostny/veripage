# 在线演示部署检查单（可选加分项）

> 评审要求：公网可访问地址 + 评审期间保持可用 + 如需登录提供测试账号。
> VeriPage 无登录体系（第三条天然满足），关键是前两条。
> **重要边界（如实）**：`/scan` 链接核验需要服务端浏览器取证（Playwright + Chromium），
> Vercel Serverless 跑不了完整取证流程；**公网演示推荐 Docker 自托管**（云服务器/内网穿透均可）。
> `/text` 文本线无浏览器依赖，Vercel 可完整跑。

## 方案 A：Docker 自托管（推荐，全功能）

前置：一台可公网访问的机器（云服务器或本机 + 内网穿透），已装 Docker。

```bash
# 1. 拉代码
git clone https://github.com/mostny/veripage && cd veripage

# 2. 配置模型（ StepFun 或任意 OpenAI 兼容端点）
cp .env.example .env
# 编辑 .env：VERIPAGE_AGNES_BASE_URL / VERIPAGE_AGNES_API_KEY 填真实值

# 3. 构建并启动（镜像内含 Chromium + Noto CJK 中文字形，非 root 运行）
docker compose up -d --build

# 4. 验证
curl -I http://127.0.0.1:3000        # 200 即 OK
```

公网放行：
- 云服务器：安全组放行 3000（或反代 80/443 → 3000，建议加 HTTPS）
- 本机演示：`cloudflared tunnel --url http://localhost:3000` 或 frp/花生壳内网穿透，得到 https 临时域名

评审期间可用性：
- `docker compose up -d` 已后台常驻；建议加 `restart: unless-stopped`
- 模型 API Key 余额提前充值确认；/scan 一次全流程约 1-2 万 tokens
- 提交前自测一轮：`/scan` 扫 `https://www.wikipedia.org/`、`/text` 贴一段话，都出报告即正常

## 方案 B：Vercel（仅文本线完整）

1. GitHub 账号导入仓库 → Import
2. 环境变量配置（Settings → Environment Variables，**必配否则检测功能不可用**）：
   - `VERIPAGE_AGNES_BASE_URL` = 模型端点
   - `VERIPAGE_AGNES_API_KEY` = 模型 Key
3. Deploy（vercel.json 已含 regions=hkg1 与 API 时限配置）
4. 验收口径：`/`、`/text` 完整可用；`/scan` 可展示界面与静态部分，浏览器取证受限——**在提交材料的演示说明里如实写明，避免评审误判为故障**

## 提交时需要填的内容

- 演示地址：`https://<你的域名或隧道地址>`
- 体验账号：无需登录，直接使用
- 演示引导语（可贴在提交备注）：
  > 打开首页 → 顶部「链接核验」粘贴任意可疑网址（示例：https://www.wikipedia.org/ 观察正常站点如何被交叉核验）→「文本体检」粘贴含手机号/身份证的文本，观察本地脱敏与 AIGC 判定。全程无需注册。

## 成本与风险提示

- 模型费用：评审期间每人每次 /scan 约 1-2 万 tokens；如担心滥用，可设限流（compose 前挂 nginx limit_req）或用低额度子 Key
- 公网开放边界：项目已建立 S0 准入、浏览器沙箱、非 root 容器；采集进程与模型凭据分离、网络出口隔离尚未建立（README 如实声明）——评审演示流量可控，风险可接受
