## 3. 补充诊断中实际复现的问题

以下为现有行为，不是已经修复的结果。

### 3.1 IPv4 映射 IPv6 内层回环误放行

纯函数/URL 入口检查，不建立目标连接：

```text
输入 URL: http://[::ffff:127.0.0.1]/
URL 规范化主机: [::ffff:7f00:1]
isPrivateIp: false
assertPublicHttpUrl.allowed: true
```

源代码只对点分写法专门拆内层 IPv4，规范化十六进制形式未正确分类。这是访问边界问题，应先补失败回归再修复；不能被原有 14 个 guard 断言通过掩盖。

### 3.2 可注册主域解析错误

```text
getRegistrableDomain('login.example.co.uk')
当前返回: co.uk
应展示的可注册域名: example.co.uk
```

这是身份核验基础事实错误，可能影响品牌、脚本跨域与授权关系判断。

### 3.3 空依据推断和重复 coverage 被接受

构造纯内存合成快照：risk 为 high，evidence 为空，唯一 inference 的 evidenceIds 为空，并有两条 validate coverage。当前 `validateSnapshot` 返回：

```json
{ "ok": true, "errors": [] }
```

它证明结构校验存在具体遗漏，不证明任意一份真实报告都出现了该问题。

### 3.4 实际拒绝报告存在 validate 双写

上述 HTTP 拒绝路径 report 中，`coverage.filter(step === 'validate').length` 实测为 **2**。追踪到 `finalizeSnapshot` 直接 push 后再调用也会 push 的 emitStep。
