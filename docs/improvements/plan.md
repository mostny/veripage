## 1. 改进目标与范围

围绕一条链接完成“真实取证 → 身份核验 → 证据解释 → 本地保存与个人复核”，优先解决不可信结论与异常状态，再完成有辨识度的证据工作台。

- 保留 Next.js 16 / React / TypeScript / Tailwind / Playwright，不以换栈为目标。
- 延续风险、证据充分程度、检测覆盖三个独立维度。
- 案例与复核以 IndexedDB 为主；后端只维护受控取证、模型接入和短期任务/产物。
- 不增加账号组织、多人审批、支付、生产向量数据库或自由递归多 Agent。
- 新依赖按实际缺口最小引入。核心测试优先用 `node:test`，浏览器测试复用已有 Playwright。
- 原始模型判断与用户复核分离；回放与实时执行分离；未经验证的模型输出不包装成确定性事实。

这些是本项目打磨方案，不是额外的赛事硬性要求。

## 5. M1：先修事实纪律、访问边界与任务终态

### M1-A 输入与访问边界

**修改范围：** `lib/guard/access.ts`、`lib/tools/url-static.ts`、`lib/tools/fetch-page.ts`；抽取共享 URL 解析模块，供首页/API/静态分析调用。

1. 对 IPv6 规范化后识别 IPv4 映射地址，再按内层 IPv4 判断；补充相关保留地址测试，不只拦截点分写法。
2. 用维护 PSL 的解析实现替换少数后缀枚举，明确 IP、单标签、私有后缀的处理；保留真实 hostname 与可注册域名的区别。
3. 输入统一处理协议、userinfo、长度和敏感参数；展示/模型/日志使用最小化后的 URL。不能为了脱敏改变实际采集目标。
4. 真实浏览器采集采用保留沙箱的非 root 执行环境，取证进程不持有模型凭据；通过网络出口策略约束私网、跳转和子资源。DNS 缓存不是连接固定或网络隔离。
5. 默认禁止写入型请求、下载、弹窗扩散和任意点击；约束 Service Worker/WebSocket 等非普通路由路径。允许/拒绝事件进入覆盖限制，而不是悄悄修改页面。
6. 给时间、并发、页面高度/截图像素、响应体积和临时产物设置显式上限；与已存在的 20 秒页面预算、120 秒整体预算衔接。

**验收：**

- [ ] 规范化后的 IPv4-mapped IPv6 回环/私网均拒绝，纯函数与 URL 入口测试均覆盖。
- [ ] `example.co.uk`、`com.cn`、多级子域、IP/IDN 的真实域名展示正确；域名相似不直接判恶意。
- [ ] 在隔离测试环境验证私网跳转、子资源、DNS 重绑定；以实际连接记录证明网络边界，不能只看 guard 返回值。
- [ ] 未具备隔离环境时，用 fixture/mock 完成其他开发；不把生产 guard 改成允许 localhost 来跑靶场。

### M1-B 证据与裁决

**修改范围：** `lib/evidence/types.ts`、`validate.ts`、`lib/agent/orchestrator.ts`、`lib/prompts/analyzer.ts`。

1. 保存每类采集结果的状态，区分“成功且为空”“部分采集”“失败”“未执行”。只有成功检查的空表单才可写“未发现表单”。
2. 用同一份规范化证据构建模型输入和最终快照；当前正文传模型 3,000 字而快照 excerpt 截为 1,200 字，需避免结论依赖保存后找不到的内容。
3. 视觉模型描述保留模型来源与截图绑定，不能自动视为确定性的 DOM 观察事实；缺失占位进入 gaps/coverage，而不是支撑风险结论。
4. 无依据事实不再静默改标推断。允许一次受预算约束的修复；仍无依据则移除具体结论、明确分析不完整，并重新核对风险摘要。
5. 推断引用链必须能到达真实证据，检查空引用、循环、无根链、重复/冲突 id；结构校验不能宣称保证语义正确。
6. coverage 采用“一步骤一条最终状态”，事件可以更新，快照不重复；partial/skipped/failed 说明原因。修复 validate 双写。
7. 硬校验失败不能只加 `[校验未过]` 前缀后继续展示同等确定的高风险/低风险结论；保留有效证据，给出受限报告。

**验收：**

- [ ] DOM 采集失败不产生“无表单/无外部脚本/无跳转”事实。
- [ ] 同一证据的保存内容、传模内容与定位范围一致。
- [ ] 空引用、循环推断、失效引用和缺失截图占位不能成为有效依据。
- [ ] validate 在快照中恰好一条；截图或 DOM 失败时覆盖状态准确。
- [ ] 原有合法快照与规则兜底回归保留；schema 有版本，旧数据兼容策略明确。

### M1-C 任务生命周期

**修改范围：** `app/api/scan/route.ts`、`lib/agent/orchestrator.ts`、`lib/models.ts`、`lib/tools/fetch-page.ts`、`app/scan/page.tsx`；新增共享事件契约和客户端扫描 hook。

1. 统一事件类型，区分任务状态（running/completed/failed/cancelled）与步骤覆盖状态；成功只发一次最终 report，失败/取消有明确终态。
2. route 创建统一 taskId 并传给编排器/产物存储，快照 caseId 如不同需有显式映射。
3. request abort、流 cancel 和总超时传递同一个取消信号；模型 fetch/重试退避、浏览器上下文与临时文件真正停止/释放。Promise.race 本身不算取消。
4. 前端用 AbortController 和请求代际 id 防止重复检测串流；换 URL/卸载时取消旧请求。
5. SSE 支持跨块 UTF-8、CRLF、尾帧冲刷；意外 EOF 没有 report 时停止转圈并提示中断。缺少 URL 直接给空状态。

**验收：**

- [ ] 正常成功、HTTP 400、总超时、模型错误、客户端中断均有可操作的终态。
- [ ] 快速重试或切换 URL 后，旧任务不能覆盖新报告。
- [ ] 取消后浏览器被关闭，模型连接被取消，不再继续有限重试或补证。
- [ ] 每条重要分支用 fake fetch/clock/dependency seam 验证，不靠等真实 120 秒。

- 对未来新增行为使用明确断言，不把只打印输出的脚本当成回归测试。
- 比较规则、同一基础模型直接分析、完整方案及关键模块消融；报告误报、拒判、证据支持、耗时和成本，不追求虚假的单一准确率。
- 性能先测截图大小、报告切换、首屏和一次核验耗时，再决定压缩/懒加载/缓存；未经测量不承诺秒数。
- 最后做文案、对比度、响应式、空状态和错误状态的一致性检查。浏览器截图/功能测试分别证明视觉和行为，不互相替代。

## 11. 协作、提交与回归方式

建议按可回退的小提交推进，示例顺序：

1. `test: add offline boundary and evidence regressions`
2. `fix: validate normalized hosts and evidence provenance`
3. `fix: terminate and cancel scans consistently`
4. `feat: deliver session-isolated screenshot artifacts`
5. `feat: link findings with evidence workbench`
6. `feat: retrieve verified identity explanations`
7. `feat: persist local cases and review events`
8. `test: cover end-to-end success and failure journeys`

这是后续提交建议，不代表这些提交已经产生。保留现有测试；修复测试遗漏，而不是移除难例或降低断言。

多人协作时，先统一 `lib/evidence` 和事件/产物接口，再并行：核心流水线、前端工作台、样本/存储测试。`orchestrator.ts` 和共享契约由单一负责人集成，避免多个分支同时大改。

每阶段检查：`next typegen → tsc → lint → 离线测试 → build`；涉及页面再补浏览器行为/视觉观察。合并前重新核对远端新增提交，不能覆盖其他协作者工作。
