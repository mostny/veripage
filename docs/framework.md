# 网鉴 VeriPage · 大题框架

> 第九届传智杯 AI WEB 网页开发挑战赛 · 赛道方向：AI 安全与内容治理
> 对应官方命题：「利用 AI 技术构建内容安全检测、隐私保护、AI 生成内容识别等安全类 Web 应用，体现负责任 AI 的设计理念」

## 1. 定位与核心主张

**网鉴 VeriPage = 核验网页「声称的身份」与「实际行为」是否一致的 AI 安全检测台。**

核心主张：不是"识别危险"，而是**核验身份一致性**——通过页面视觉、语义和技术证据，判断"它声称自己是谁"与"它实际在做什么"是否吻合。

相比三类既有方案的差异化：

| 既有方案 | 解决不好的问题 | 我们的答案 |
|---|---|---|
| 黑名单（PhishTank 等） | 只认识已报案的新站，0day 钓鱼站天然漏网 | 证据核验不依赖历史报案 |
| 直接问聊天 AI | 模型打不开链接、看不到页面，只能凭 URL 字面猜 | 沙箱代访 + 视觉/语义/技术三路取证 |
| 传统网页取证工具 | 输出原始数据，普通人看不懂，也不判断"仿冒谁" | 四问框架 + 证据三级标注的可解释报告 |

## 2. 产品三层

| 层 | 模块 | 输入 → 输出 | 服务的评分点 |
|---|---|---|---|
| L1 核验引擎 | 身份一致性核验 | URL / 截图 → 带证据链的风险报告 | AI 深度 35% + 创新 25% 主力 |
| L2 文本体检 | 内容安全体检 | 一段文本 → AIGC 识别 + 隐私脱敏 | 官方点名"隐私保护 / AIGC 识别"两项可见 |
| L3 治理体验 | 报告交互与复核 | 结论 ↔ 证据联动、双层视图、人工复核 | 用户体验 10% + 负责任 AI |

## 3. 核验四问（L1 的系统骨架）

| 核验对象 | 具体问题 | 取证来源 |
|---|---|---|
| 身份声明 | 页面声称属于哪个机构？ | 页面标题/文案/品牌词（语义模型） |
| 视觉语义 | 是否模仿该机构？索要什么操作？ | 截图 → 视觉模型 |
| 技术事实 | 实际域名、跳转链、表单提交目标？ | 沙箱抓取（确定性，非模型） |
| 合法解释 | 是否存在已核验的第三方登录等正常解释？ | 官方域名/授权登录白名单库（RAG） |

## 4. 三道闸门（检测流水线）

```
输入 URL/截图
   ↓
① 字符串分析（不访问，毫秒级，纯确定性规则）
   域名编辑距离（ta0bao↔taobao）· 子域伪装拆穿（taobao.com.xxx.cn → 真域名 xxx.cn）
   punycode 同形字符 · 短链展开预判 · 黑名单比对 · URL 参数 payload 痕迹
   ↓ 初步信号
② 沙箱代访（秒级，Playwright 无头浏览器，机器替人"点"）
   跟随全部重定向记录跳转链 · 抓最终 HTML + 渲染截图
   提取硬证据：表单 action 指向 / 外部域脚本清单（反代钓鱼指纹）
   ↓ 结构化证据
③ AI 取证（agnes-2.5-flash：文本+视觉+原生工具调用）
   视觉看截图（仿冒谁）· 语义看 HTML（话术/索要行为）
   白名单/案例库比对（合法解释 + 相似案例引用）
   ↓
风险报告：结论分级 + 每条结论绑定证据
```

**自适应原则**：发现信息缺口才调对应工具补证（如文本太少才加视觉）；证据充分即停；访问失败输出"取证不完整"而非硬猜。

## 5. 证据模型（原创实现重点）

每条结论必须绑定证据，三级标注：

- **观察事实**：页面包含密码输入框（截图/DOM 可指认）
- **风险推断**：可能在索取账号凭据（由事实推出，标明推理链）
- **未知事项**：无法确认该第三方登录是否获官方授权

程序化校验：结论引用的 evidence id 必须存在于证据池（不止校验 JSON 可解析）。边界纪律：**未提交表单 ≠ 证实凭据流向；授权未知 ≠ 判定冒用**。

## 6. 负责任 AI 实践（对齐官方设计理念）

1. 可解释：报告"为什么这么判"面板，每条结论挂证据
2. 拒答兜底：无依据拒答、JSON 解析失败自动重试、超时降级纯规则结果
3. 边界声明：「未检出 ≠ 安全」常驻报告页脚；存储型/DOM 型 XSS 明示不可靠检出
4. 数据伦理：用户提交内容不留存声明页；密钥仅服务端环境变量
5. 抗操纵：页面内容一律视为不可信数据（抗提示注入加固 + 靶场样本验证）
6. 人工复核：检测 → 标记误报 → 待复核列表 → 更正留痕（轻量版）

## 7. 技术栈与仓库结构

- **栈**：Next.js 16（App Router）+ TypeScript + Tailwind 4 + shadcn/ui；模型 agnes-2.5-flash（OpenAI 兼容 REST，原生 Function Calling + 视觉 + 流式，见 docs/model-notes.md）；沙箱 Playwright
- **结构**：

```
app/            首页 / scan/[id]（SSE 检测过程+报告）/ text / review / about
lib/agent/      自适应取证编排（缺口→工具→停止条件）
lib/tools/      六工具：url-static / fetch-page / vision-analyze / content-analyze / kb-lookup / rag-search
lib/evidence/   证据结构：三级标注 + 结论-证据绑定校验
lib/prompts/    系统提示（含抗注入加固）
knowledge/      钓鱼案例库 + 官方域名/授权登录白名单（JSON 带来源）
testpages/      自建可控靶场（仿冒/注入样本，标注演示用）
eval/           环境探测 / 三组对照实验 / 测试集
docs/           本框架 / 模型实测 / 技术文档源
```

## 8. 实验设计（W3，喂"测试与评估"章）

- 三组对照：A 黑名单+规则（只跑闸门①）vs B 纯模型直判（无工具）vs C 完整方案
- 消融：去视觉证据 / 去白名单库
- 必报指标：检出率、正常页误报率、无法判定率、证据支持率、注入抵抗力、单次耗时
- **单独报告黑名单未命中子集**（证明 AI 必要性）
- 测试集 30~50 URL：正常站含 SSO / 相似域名合法站 / PhishTank 仿冒 / 自建靶场 / 不可达页

## 10. 能力边界（诚实声明，进报告页脚与技术文档）

- 可靠检出：假站仿冒 / 反代钓鱼指纹 / 恶意跳转链 / URL 层 XSS 痕迹
- 不可靠检出（如实标注）：存储型 XSS / DOM 型 XSS（需运行时行为监控，超出定位）
- 演示样本全部自建可控并标注"演示用"，不依赖现场恶意站点
